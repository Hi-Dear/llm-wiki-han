# 하네스 엔지니어링 (Harness Engineering)

2026년 2월 Mitchell Hashimoto가 최초로 언급한 개념. 프롬프트에 "하지 말라"고 써도 에이전트가 같은 실수를 반복하는 경험에서 출발했다.

> **하네스 엔지니어링** = 에이전트가 실수할 때마다, 그 실수가 다시는 반복되지 않도록 **환경 자체를 엔지니어링**하는 것.
> 하네스(harness) = 마구(馬具): 인간의 의도대로 컨트롤하게 하는 장치.

## AI 활용 기술의 발전 흐름

1. **프롬프트 엔지니어링** — AI에게 말을 잘 거는 기술
2. **컨텍스트 엔지니어링** — AI가 내 상황(맥락)을 이해하게 하는 기술
3. **MCP + 스킬** — AI가 쓸 도구를 정해주는 기술(MCP)과 도구 가이드라인(스킬)
4. **하네스 엔지니어링** — 스킬과 MCP가 너무 많아져 오히려 AI가 헷갈리는 문제를, **환경 자체를 설계**해서 해결하는 기술

## 왜 필요한가

- **컨텍스트 부패**: 컨텍스트 창이 꽉 차면 앞의 내용을 잊어 절반만 구현하고 조기 종료함
- **규칙과 울타리 부재**: 구조적 제약이 없으면 위험한 행동 가능 (예: 결제 시스템을 만들라 했는데 DB를 삭제)

해결 장치:
- **CLAUDE.md**: 클로드는 새 세션마다 이 파일을 1순위로 읽음 → 리셋되는 기억을 잡아줘 컨텍스트 부패와 규칙 문제를 해결. [[LLM Wiki 패턴]]의 Schema 계층이 바로 이것
- **훅(Hooks)**: AI의 행동 흐름 사이에 끼어들어 안전검사·자동 실행을 강제하는 제어장치

비유: 하네스 엔지니어링은 **공장 안전 시스템**이다.

## 하네스의 구성 요소

1. **컨텍스트 파일** (`AGENTS.md` / `CLAUDE.md`)
   - 세부 내용은 별도 파일로 분리
   - 실패할 때마다 한 줄씩 추가 — 처음부터 완벽할 필요 없음
2. **자동 강제 시스템** (Linter, Pre-commit Hook)
   - Linter: 코드 맞춤법 검사기, 위반 시 자동 에러
   - Pre-commit Hook: 저장(커밋) 전 자동 검사
   - 피드백 루프를 수행
3. **가비지 컬렉션**
   - 기존의 나쁜 패턴을 따라 하지 못하게 제거 → 청소 에이전트를 만들 것
